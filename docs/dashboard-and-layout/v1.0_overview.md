# Dashboard & Layout 🖥️

This section describes the overall user interface structure of SynchroFlow and the functionality of the main dashboard, including customization options.

---

## Core Layout Philosophy (v6.0+)

SynchroFlow employs an **Entity-Centric** design built upon a flexible, two-panel system powered by `react-resizable-panels`:

1.  **Master Panel (Left)**: Typically displays a list or overview of a core entity type (e.g., Orders, Customers). It uses the `MasterPanel` component shell.
2.  **Context Panel (Right)**: Displays detailed information and actions related to the item selected in the Master Panel. It uses the `ContextPanel` component shell, often featuring tabs for organizing complex information (e.g., Order Summary, Order Items, Customer History).
3.  **Sidenav**: Provides primary navigation between the main entity views (Orders, Customers, Products, Echo Inbox) and the Dashboard.
4.  **Header**: Contains global elements like search, notifications, user profile, and the customization drawer.

This structure ensures that relevant context is always readily available, minimizing the need to jump between different screens for related information. 

---

## The Main Dashboard (`/dashboard`)

The main dashboard serves as the **C-Suite/Managerial Overview** for the entire operation. It provides a high-level, customizable view of key performance indicators (KPIs) and operational health metrics.

* **Technology**: Built using `react-grid-layout`, allowing users to resize and rearrange widgets.
* **Purpose**: To quickly assess business performance, identify potential issues, and track the value SynchroFlow provides (especially Opex savings).
* **Key Widgets (Initial)**:
    * **KPI Cards**: Displaying core metrics like Gross Revenue, Gross Margin, Inventory Value (using the `KpiCard` component).
    * **A-Opex Gauge**: The flagship widget showing calculated operational expenditure savings attributed to SynchroFlow's automation (using the `AOpexGauge` component). 
    * **Cash Flow Widget**: Visualizes historical and potentially projected cash flow (using `ReactApexChart`).
    * **Inventory Health Widget**: Summarizes stock levels across SKUs (using `MainCard` and MUI `Table`).

## Layout Customization 🔧

SynchroFlow offers robust personalization options, allowing users to tailor both the dashboard layout and the overall application appearance to their preferences and workflow needs.

### **Dashboard Widget Management**

The main dashboard (`/dashboard`) is designed for flexibility using `react-grid-layout`.

* **Edit Mode**: A dedicated **"Edit Layout"** button (likely in the `AppLayout` header or near the dashboard title) toggles the grid's edit state.
    * **When *enabled***:
        * **Drag & Drop**: Widgets can be freely repositioned by clicking and dragging their header or main body. 
        * **Resize**: Resize handles appear (typically on the bottom-right corner) allowing users to change the width (`w`) and height (`h`) of each widget within the grid constraints.
        * **Remove**: An "X" icon appears on each widget (often top-right) allowing users to remove it from their current view.
    * **When *disabled***: The layout is locked, preventing accidental changes during normal use.
* **Adding Widgets**: The **"Add Widget"** button opens the **Widget Library** panel/modal.
    * This library displays all available widgets based on the `WIDGET_REGISTRY`.
    * Widgets may be **gated** based on the user's `currentUserPlan` (`Ignition`, `Clarity`, etc.).
    * Clicking an "Add" button for a widget places a new instance onto the dashboard grid (typically at the top or first available slot).
* **Saving**: Layout modifications (position, size, active widgets) are automatically persisted.
    * When the user exits "Edit Mode" (e.g., by clicking a "Save Layout" button which replaces the "Edit" button), the current `layout` and `activeWidgets` state is sent via a `POST` request to the `/api/v1/layouts/dashboard` endpoint.
    * This ensures the user's customized dashboard is loaded the next time they visit.

### **Theme Customization (Global)**

Global look-and-feel adjustments are managed via the **Customization Drawer**, accessed through a **settings/cog icon (⚙️)** in the application Header. This utilizes Berry's theme engine and `ConfigContext`.

* **Theme Mode**: Toggles between **Light**, **Dark**, or syncing with the user's operating **System** preference. This affects background colors, text colors, and component appearances across the entire application. 
* **Preset Colors**: A selection of predefined color palettes (e.g., "Default", "Blue", "Indigo"). Selecting a preset updates the application's primary, secondary, and related theme colors (buttons, highlights, charts, etc.).
* **Font Family**: Allows selection from available fonts (e.g., Roboto, Inter, Poppins) defined in the theme.
* **Border Radius**: A slider or input to adjust the global border radius, affecting the roundness of components like buttons, cards, and inputs.
* **Persistence**: All theme choices are saved to the user's browser **local storage** via the `ConfigContext` provider. This ensures the selected theme is reapplied automatically on subsequent visits without needing backend storage for purely visual preferences.

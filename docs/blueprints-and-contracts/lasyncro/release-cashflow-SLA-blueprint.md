# 🔒 LaSyncro — Release & Cash-Flow SLA Blueprint

**Canonical · Conservative · Enforceable**

---

## 1. PRIME GOVERNING LAW (APPLIES EVERY MONTH)

> **Truth completeness gates releases.
> Cash sufficiency gates ambition.
> Violation of either triggers slowdown, not acceleration.**

---

## 2. RELEASE SLA — WHAT MAY SHIP, WHEN, AND UNDER WHAT CONDITIONS

### 2.1 Release Unit SLA (Non-Negotiable)

A release is allowed **only if all conditions are met**:

| SLA Check        | Requirement                                        |
| ---------------- | -------------------------------------------------- |
| FT2 completeness | Facts → Intelligence → FTEP → UI fully implemented |
| Null safety      | 100% null-safe in UI & API                         |
| Coverage exposed | Every signal has coverage/freshness                |
| No semantics     | No explanations, no advice, no prioritization      |
| Trust compliance | Trust FT2 passes (else downgrade to null)          |
| Rollback ready   | One-click disable of new surface                   |

❌ Partial modules forbidden
❌ Feature flags visible to users forbidden

---

### 2.2 Canonical Release Cadence

| Phase              | Release Frequency     | Rule                     |
| ------------------ | --------------------- | ------------------------ |
| Internal (Phase 0) | As needed             | No users, no pressure    |
| Alpha (Phase 1)    | Every 8–12 weeks      | Only bug-fix releases    |
| Paid v1–v2         | Every 12–16 weeks     | One module/submodule max |
| Post-CNS           | Max 2 releases / year | Stability > novelty      |

> **If you feel “behind schedule”, you are probably safe.**

---

## 3. MODULE RELEASE SLA (LOCKED ORDER)

| Phase | Allowed Module Release                 | SLA Gate                     |
| ----: | -------------------------------------- | ---------------------------- |
|     0 | Orders FT2 · Trust FT2                 | Zero lies under nulls        |
|     1 | Customers FT2                          | No interpretation questions  |
|     2 | Products FT2 · Inventory FT2 · Returns | Paid conversion ≥ 5%         |
|     3 | WMS Lite                               | Inventory coherence proven   |
|     4 | Finance FT2                            | Cash presence accuracy ≥ 99% |
|     5 | SKU Integrity · Full Alignment         | CNS completeness reached     |

❌ Skipping phases forbidden
❌ Parallel module launches forbidden

---

## 4. CASH-FLOW SLA — MONTHLY OPERATING GUARDRAILS

### 4.1 Monthly Burn SLA

| Metric           | SLA Threshold                      |
| ---------------- | ---------------------------------- |
| Monthly burn     | ≤ 110% of prior 3-month average    |
| Infra growth     | ≤ 20% QoQ                          |
| Founder comp     | Fixed per year, no mid-year raises |
| Tools/SaaS creep | Reviewed quarterly                 |

If exceeded → **freeze releases & scope**

---

### 4.2 Runway Protection SLA

| Runway Remaining | Mandatory Action            |
| ---------------- | --------------------------- |
| ≥ 18 months      | Normal operations           |
| 12–18 months     | Freeze new modules          |
| 9–12 months      | Only bug fixes + conversion |
| < 9 months       | Cost cuts + no releases     |

> **Running out of runway invalidates all product decisions.**

---

## 5. REVENUE & CONVERSION SLA (OBSERVATIONAL, NOT OPTIMIZED)

These are **monitoring signals**, not goals.

| Signal                                       | Healthy Range           | Action if Violated               |
| -------------------------------------------- | ----------------------- | -------------------------------- |
| Free → Paid conversion                       | 3–7%                    | Do NOT add features              |
| Paid churn                                   | < 4% monthly            | Investigate trust breaks         |
| Upgrade rate                                 | Slow but steady         | Accept slowness                  |
| Support questions asking “what should I do?” | High early, lower later | If zero → product too comforting |

❌ No growth hacking
❌ No pricing experiments mid-phase

---

## 6. RELEASE ↔ CASH COUPLING SLA (CRITICAL)

### You may NOT:

* ship a new module while burning > plan
* expand infra before paid uptake
* add integrations to “increase value”
* accelerate roadmap to close deals

### You MUST:

* slow releases when cash tightens
* favor depth over breadth
* preserve FT2 discipline even under revenue pressure

---

## 7. INCIDENT & ROLLBACK SLA

| Incident                | Required Response      |
| ----------------------- | ---------------------- |
| Truth misinterpretation | Immediate UI downgrade |
| Intelligence leak       | Same-day rollback      |
| Coverage hidden         | Emergency patch        |
| Sales promise mismatch  | Public correction      |

> **Trust incidents are higher priority than outages.**

---

## 8. MONTHLY GOVERNANCE CHECKLIST (MANDATORY)

Every month, founders must answer **yes/no only**:

1. Did we ship any partial truth?
2. Did we hide any blindness?
3. Did we add anything “helpful”?
4. Did cash pressure influence roadmap?
5. Did we explain instead of expose?

If **any “yes” appears** → pause, rollback, correct.

---

> **LaSyncro is governed like infrastructure,

* Slow releases
* Predictable spend
* Ruthless rollback

If this SLA is broken:

# LaSyncro Theme Architecture

This document explains the A-Z flow of how the Material UI theme is applied in the LaSyncro frontend, from the root of the app to the final color definition.

## 1. The Component Hierarchy

The theme system is split into two parts:
1.  **State Management (`<ConfigProvider>`):** Holds the *settings* (e.g., "blue" preset, 8px border).
2.  **Theme Engine (`<ThemeCustomization>`):** Takes those settings and *applies* them to the app.

The component tree looks like this:

<main.tsx> <ConfigProvider> <App.tsx> <ThemeCustomization> <CssVarsProvider> <CssBaseline /> [...Your Routes...] </CssVarsProvider> </ThemeCustomization> </App.tsx> </ConfigProvider> </main.tsx>


---

## 2. The Data Flow (A-to-Z Trace)

This is how a setting flows from a user click to a visual change.

### Step 1: `main.tsx` (The Entry Point)
* **File:** `apps/frontend/src/main.tsx`
* **Job:** Renders the root of the app.
* **Key Line:** It wraps the entire app in `<ConfigProvider>`. This component's only job is to provide the `ConfigContext`, which holds the global state for `presetColor`, `fontFamily`, etc.

### Step 2: `App.tsx` (The App Shell)
* **File:** `apps/frontend/src/App.tsx`
* **Job:** Renders the application routes.
* **Key Line:** It wraps all `<Routes>` in the `<ThemeCustomization>` component.

### Step 3: `themes/index.tsx` (The Theme Engine)
* **File:** `apps/frontend/src/themes/index.tsx`
* **Job:** This is the most important file. It connects the **State** to the **Engine**.
* **Process:**
    1.  It uses the `useConfig()` hook to subscribe to the `ConfigContext` (from Step 1).
    2.  It calls `buildPalette(presetColor)` from `palette.ts`.
    3.  It calls `Typography(fontFamily)` from `typography.ts`.
    4.  It passes all these objects into MUI's `extendTheme()` function.
    5.  It renders the *real* MUI theme provider: `<CssVarsProvider theme={themes}>`.
    6.  It renders `<CssBaseline />`, which tells the browser to apply the theme's background color to the `<body>` tag.

### Step 4: `palette.ts` (The Palette Builder)
* **File:** `apps/frontend/src/themes/palette.ts`
* **Job:** Defines *what* "light" and "dark" modes look like for any given color preset.
* **Process:**
    1.  It exports the `buildPalette()` function.
    2.  This function calls `getColorsById()` from `presetColors.ts` to get all color values.
    3.  It returns two objects:
        * `lightColors`: Sets `background: { default: colors.grey100 }`.
        * `darkColors`: Sets `background: { default: colors.darkPaper }`.

### Step 5: `presetColors.ts` (The Source of Truth)
* **File:** `apps/frontend/src/themes/presetColors.ts`
* **Job:** This is the absolute source of truth for all color hex codes.
* **Key Object:** The `baseColors` object defines our core light/dark theme colors:
    * `grey100: '#eef2f6'` (The correct light mode background)
    * `darkPaper: '#121212'` (The correct dark mode background)

## 3. How Changes are Triggered

* **Light/Dark Mode:**
    * **File:** `layout/Customization/ThemeMode.tsx`
    * **Action:** A user clicks a button.
    * **Mechanism:** It calls the `useColorScheme().setMode()` hook.
    * **Target:** This hook talks *directly* to the `<CssVarsProvider>` (in `themes/index.tsx`), which then swaps the active CSS variables.

* **Preset Color (e.g., "Blue" to "Orange"):**
    * **File:** `layout/Customization/PresetColor.tsx`
    * **Action:** A user clicks a color swatch.
    * **Mechanism:** It calls `dispatch({ type: 'SET_PRESET_COLOR', ... })`.
    * **Target:** This updates the `ConfigContext` (from `main.tsx`). This causes `themes/index.tsx` to re-render, call `buildPalette()` with the new color, and generate a *new theme* for the `<CssVarsProvider>`.
